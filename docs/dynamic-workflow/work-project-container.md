# Work 模式「项目工作流」容器

本规格定义 work 模式里的项目级工作流聚合视图。它是**只读投影**：不新增协议、不迁移数据、不复制已保存工作流的写路径，创建、修订、运行仍由「已保存工作流」中枢和对话承担。

## 背景与边界

- 现状：已保存工作流按项目分散在 `~/.zcode/workflows/`，中枢页按项目分组展示；work 模式没有把「我这个项目有哪些工作流」放在主视图的入口。
- 目标：在 work 模式提供项目级聚合入口，让用户不离开 work 模式就能看到本项目（及已打开项目）保存的工作流。
- 非目标：成员协作、跨项目编排、项目级权限；这些不在本切片内。

## 状态与所有者

| 状态                  | 所有者                                      | 说明                                                   |
| --------------------- | ------------------------------------------- | ------------------------------------------------------ |
| 工作流列表 / 运行历史 | `savedWorkflowStore`（读投影）              | 容器只读；写入仍走中枢的既有动作                       |
| 项目列表              | `useSavedWorkflowProjectOptions`            | 与中枢同源，含远程项目过滤规则                         |
| 详情态                | 容器本地 state                              | 按项目 workspaceKey 记录当前详情的工作流名             |
| 关停开关              | localStorage `zcode:work-project-workflows` | 缺省开启；`0/false/off/no`（大小写、空白不敏感）为关闭 |

## 入口与可见性

- 侧栏导航新增「项目工作流」，仅在 work（office）模式、且关停开关未关闭时出现。
- 主视图 key 为 `project-workflows`；从该视图返回时回到对话主视图。
- 关停开关关闭时：入口隐藏，且不渲染主视图内容（fail-closed，不残留空白页）。

## 页面行为

1. 页头：标题、说明、`Work 模式` 标记与刷新按钮。
2. 按项目分组，复用中枢的项目组组件：组头含项目名、「当前」标记、数量与「通过对话创建」。
3. 每组独立加载、空态、错误态；单组失败不影响其他组。
4. 打开工作流详情只在该组内切换，返回回到列表。
5. 刷新按钮让所有组绕过缓存重拉。

## 验收场景

- 打开 work 模式 → 侧栏出现「项目工作流」→ 点击进入聚合页。
- 关闭关停开关并重载 → 侧栏入口消失，直接设置主视图也不渲染内容。
- 两个项目各有工作流 → 分组展示，数量与中枢一致。
- 空项目 → 显示空态卡，不显示加载中。
- 远程项目断连 → 该项目组按中枢规则隐藏，不阻塞其他组。
